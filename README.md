# 勇虹医疗 · 设备效益管理平台

本平台以医院为租户边界，提供大型医疗设备效益管理、分析与报告能力，当前包含：

- 医院级效益驾驶舱与单机分析
- 按设备品类配置采集链路、质量门禁、收费对账与单机核算口径
- 设备台账、成本填报和运营改进闭环
- 医院、成员、角色、数据范围与审计策略配置
- 数据源、采集分析模板、指标口径、驾驶舱布局和个人偏好配置
- 按用途分类的报告模板库、医院启用与默认分配、公共字段包和逻辑数据源映射
- 效益分析报告的编制、复核、签发、版本和 Word / CSV 导出
- 报告保存时由服务端按医院云数据重建质量结果与冻结快照，模板期间、必需来源和受控补录规则不能由前端绕过
- 当前正式报告台账、审批链和归档文件按医院级治理，仅向具备报告权限且数据范围为本医院/全平台的账号开放；科室或个人范围默认拒绝
- 消息中心、个人中心与跨设备云端同步

## 登录方式

平台支持两种正式登录方式，外加匿名演示：

- **账号密码登录（推荐）**：平台/医院管理员在“医院与权限 → 成员”中为成员分配登录账号和初始密码（首次登录强制改密）。密码以 PBKDF2-SHA256 加盐哈希存储，连续 5 次失败锁定 15 分钟；已启用验证器的账号登录时还需动态验证码。冷启动无管理员时，可通过环境变量 `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` / `BOOTSTRAP_ADMIN_EMAIL` 引导首个平台管理员。
- **统一身份网关**：保留原 Sites/网关请求头身份入口，与账号密码体系共用同一账号、会话与权限模型。
- **匿名演示**：无需账号，数据仅存在当前浏览器。

角色可按“左侧菜单勾选”的方式配置：在角色编辑器中勾选某个菜单即自动授予该菜单所需权限，也可在功能权限清单中逐项微调。

## 数据保存方式

系统区分正式账号和匿名演示两种模式：

- **正式账号**：登录并通过医院成员关系校验后，医院业务数据保存在云端 D1；正式报告文件归档到 R2；主题、缩放、医院等个人偏好按账号同步。相同账号或同一医院的授权账号可跨设备使用。
- **匿名演示**：数据只保存在当前浏览器的 `localStorage`，便于无账号快速体验，不会与正式医院数据互通。

所有正式接口都会同时校验登录身份、医院成员关系、角色权限和医院范围。前端切换医院或修改请求参数不能绕过服务端权限。

## 数据准备中心隐藏入口

在左侧品牌区 4 秒内连续点击 3 次，输入入口口令（默认 `yonghong`，可用环境变量 `DATA_WORKBENCH_ENTRY_PASSWORD` 覆盖）后进入数据准备中心；平时左侧菜单不显示任何数据准备入口。口令只是入口捷径，真正的边界仍是服务端的 `connector.manage` 与 `data.*` 权限校验。

## 本地运行

环境要求：Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

浏览器访问开发服务器显示的本地地址，通常为 `http://localhost:3000`。

提交前验证：

```bash
npm run lint
npm test
git diff --check
```

## 现场演示

建议按 [DEMO-RUNBOOK.md](./DEMO-RUNBOOK.md) 逐项完成演示前检查。正式演示应至少准备管理员、医学装备、财务、院领导四类账号，并在两台独立设备上验证同一医院的数据同步。

## 重要边界

- 当前站点用于脱敏、聚合的产品演示，不得录入患者姓名、证件号、病历号、检查影像等个人健康信息。
- 系统中的设备、人员、医院和财务数据均为模拟数据，不可用于真实医疗、资产或财务决策。
- 正式医院试点应部署到医院批准的境内云或私有化环境，并完成等保、备份恢复、日志留存、容灾和安全评估。
