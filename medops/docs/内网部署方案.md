# 内网部署方案 —— 把系统装在医院自己的服务器上

> 适用于：**只在院内使用**、希望数据不出院区的场景。
> 与《部署手册.md》（公网腾讯云）二选一，**软件完全相同**，差别只在网络、证书和时间同步三处。
> 本文需要信息科（网管）配合，标注 🧑‍💻 的步骤请找网管办。

---

## 一、先决定：内网还是公网

| | 公网（腾讯云） | **内网（院内服务器）** |
|---|---|---|
| 数据存在哪 | 腾讯云机房 | **院内，不出院区** |
| 手机在哪能用 | 任何地方（4G/5G/家里） | **只有连院内网络时** |
| 护士长在家能补签吗 | 能 | 不能（除非院里给 VPN） |
| ICP 备案 | 必须办，1～2 周 | **完全不需要** |
| 费用 | 约 1000～2000 元/年 | **0 元**（用现有机器/虚机） |
| HTTPS 证书 | 自动申请、自动续期 | 需选方案，见第四节 |
| 时间同步 | 云平台自带 | **需确认，最容易出问题** |
| 出故障谁处理 | 你 + 我远程 | 需信息科配合（能进机房） |
| 断网影响 | 院内断外网就全院用不了 | **院内断外网不影响** |

**怎么选：**

- 数据合规要求严、或院里明确要求数据不出院 → **内网**
- 希望护士长在家也能补签、不想麻烦信息科 → **公网**
- 两者都想要 → 内网部署 + 让信息科做 VPN 或端口映射（第八节）

> 从内网换到公网（或反过来）不难：把 `data` 目录整个搬过去即可，数据不会丢。
> 所以**先内网试点、以后再说**是个稳妥的选择。

## 二、准备一台服务器 🧑‍💻

### 硬件/虚机要求（很低）

| 项 | 要求 | 说明 |
|---|---|---|
| CPU | 2 核 | 本系统很轻 |
| 内存 | 4 GB | |
| 硬盘 | 100 GB | 签名图是主要占用，够用好几年 |
| 系统 | Ubuntu Server 22.04 / 24.04 或 Debian 12 | **不要用 Windows** |

### 三种来源，按推荐顺序

1. **院内虚拟化平台申请一台虚机**（最推荐）
   如果院里有 VMware / 超融合平台，找信息科开一台虚机最省事——网管熟悉、有快照、坏了好恢复。
2. **一台闲置的服务器或工作站**
   要求能 7×24 开机。
3. **一台普通台式机**（下策但可行）
   **绝对不能用某个人正在办公的电脑**——他一关机全院就用不了了。

### 必须满足的三个条件 ⚠

- [ ] **7×24 开机**，不能有人手动关
- [ ] **接 UPS 或有市电保障**（突然断电可能损坏数据库文件）
- [ ] **放在机房或有锁的房间**，不是走廊里

## 三、网络：固定 IP 和网段放通 🧑‍💻

### 3.1 ⚠ 必须要固定 IP

向网管申请一个**静态内网 IP**（如 `10.20.30.40` 或 `192.168.1.100`），并在服务器上设为静态。

> **为什么这条最重要**：如果用自动分配（DHCP），服务器重启后 IP 可能会变。
> 而各科室墙上贴的二维码里写死的就是这个地址——IP 一变，**全院二维码集体失效**，
> 得重新打印重新贴。这是内网部署最常见的翻车点。

- [ ] 已拿到固定 IP：`________________`
- [ ] 已在服务器网卡设置中配成静态（不是 DHCP）
- [ ] 网管已在 IP 管理表中登记，避免被分配给别的设备

### 3.2 手机能不能访问到服务器

请网管确认：**护士拿手机连的那个 WiFi 网段，能否访问到服务器所在网段。**

很多医院的 WiFi 分了好几个网段（办公网 / 医疗网 / 访客网），网段之间默认互相隔离。
如果护士连的是访客网而服务器在办公网，**扫码会打不开**。

- [ ] 已确认护士常用 WiFi 可访问服务器 IP
- [ ] 若不通，请网管在防火墙放通该网段到服务器的 **80 / 443** 端口

**自测方法**：拿一部连着院内 WiFi 的手机，浏览器输入 `http://服务器IP`，能打开就通。

### 3.3 服务器本机防火墙

只需开放三个端口：

| 端口 | 用途 |
|---|---|
| 22 | 远程管理（SSH） |
| 80 | 网页 |
| 443 | 网页（HTTPS） |

## 四、HTTPS 证书：三个选项 ⚠

内网服务器没有公网 IP，**无法用《部署手册》里的自动申请方式**。三个选择：

### 方案 A：纯 HTTP（最简单）

改一行配置，不要证书。

- ✅ 五分钟搞定，零维护
- ❌ 浏览器地址栏显示"不安全"
- ❌ 登录密码在院内网络中**明文传输**（内网环境风险相对可控，但如果院里有**等保测评**要求，通常不允许）

**适合**：先试点跑起来看看效果，或院里明确说内网不要求 HTTPS。

### 方案 B：公网域名 + DNS 验证 + 内网解析（推荐 ⭐）

**你已经有域名了，这个方案最优雅**：申请一张正规证书，但让域名在院内解析到内网 IP。

原理：Let's Encrypt 的 **DNS-01 验证**方式只需要你能修改域名的 DNS 记录，
**不要求服务器有公网 IP**。证书拿到后，让院内 DNS 把这个域名指向内网服务器。

- ✅ 手机和电脑上都是正规**绿锁**，零警告
- ✅ 密码加密传输，满足等保要求
- ⚠ 需要信息科在院内 DNS 加一条解析记录
- ⚠ 证书 90 天要续一次（可脚本自动，但需要能改 DNS）

**怎么做**（简要，实施时我可以给完整命令）：

1. 用 `certbot` 的 DNS 插件（腾讯云 DNSPod 有对应插件）申请 `jx.你的域名` 的证书
2. 把证书文件放到服务器的 `deploy/certs/` 目录
3. 🧑‍💻 请网管在**院内 DNS** 添加：`jx.你的域名` → `服务器内网IP`
4. 手机连院内 WiFi 后访问 `https://jx.你的域名/xunjian/`，显示绿锁

> 注意：这个域名在**院外**解析不到（或解析到别处），这正是我们要的效果——只有院内能用。

### 方案 C：自签证书（不推荐）

自己签一张证书。

- ❌ 每台手机、每台电脑都会弹**红色警告**
- ❌ 要在每部手机上安装根证书才能消除警告——护士长会崩溃
- 只在方案 A、B 都不可行时才考虑

### 选择建议

| 你的情况 | 选 |
|---|---|
| 先试点，快速跑起来 | A |
| 正式上线，有域名 | **B** |
| 院里有等保要求 | **B** |
| 没有域名且必须加密 | C（并接受手机装证书的麻烦） |

## 五、⚠ 时间同步（内网最容易出问题的一环）

整套三级签字的"今天是哪天"完全由**服务器时间**裁决。内网服务器常常连不上公网的
时间服务器，运行几个月后时间会漂移，**签字日期就会错，而且很难发现**。

### 部署时必须确认

在服务器上执行：

```
timedatectl
```

看 `System clock synchronized:` 这一行：

- 显示 `yes` → 正常，不用管
- 显示 `no` → 按下面处理

### 处理办法（按优先顺序）

1. **让网管放行 NTP 出网**（UDP 123 端口），然后：

```
sudo timedatectl set-ntp true
```

2. **用院内 NTP 服务器**（多数医院的域控/核心交换机就是 NTP 源）——🧑‍💻 向网管索取地址，
   写入 `/etc/systemd/timesyncd.conf` 的 `NTP=` 一行，然后：

```
sudo systemctl restart systemd-timesyncd && timedatectl
```

3. **实在没有** → 手动设一次，并**每月自查一次**：

```
sudo timedatectl set-time "2026-09-01 08:30:00"
```

### 日常最简单的验证

登录管理后台首页，看右上角"服务器时间"是否等于当前北京时间。**每月看一眼即可。**

> 更多说明见《运维手册.md》第 9 节。

## 六、安装步骤（与公网版的差异）

主体照《部署手册.md》第 4 步之后执行，只有以下几处不同：

| 步骤 | 公网版 | 内网版 |
|---|---|---|
| 买服务器 | 腾讯云轻量 | 用院内机器/虚机（第二节） |
| 备案 | 必须 | **跳过** |
| 域名解析 | 公网 DNS → 公网 IP | 院内 DNS → 内网 IP（方案 B）；或不用域名（方案 A） |
| 安全组 | 云控制台 | 服务器本机防火墙 + 网管放通网段 |
| 证书 | certbot 自动 | 见第四节 |
| 时间同步 | 云平台自带 | **必须确认**（第五节） |

### 配置改动（三处）

**1. 运行安装脚本时，域名填内网地址**

```
cd /opt/medops/deploy && bash scripts/first-run.sh
```

- 方案 A（纯 HTTP）：域名处填**服务器内网 IP**
- 方案 B：填 `jx.你的域名`

**2. 方案 A 需要去掉 HTTPS 跳转**

编辑 `deploy/nginx/conf.d/site.conf`，把 80 端口那段里的跳转改为直接提供服务
（实施时我给出改好的完整文件，你直接替换即可）。

**3. 方案 A/B 都可以去掉 certbot 容器**

编辑 `deploy/docker-compose.yml`，删除 `certbot:` 那一段（它需要公网验证，内网用不上）。

> 这三处改动我可以提前做好一份**内网专用配置**放进 `deploy/intranet/`，
> 到时直接复制覆盖即可，你不用手改。需要的话告诉我。

## 八、如果以后想让院外也能访问

内网部署后若护士长提出"想在家补签"，有三条路，**都需要信息科同意**：

| 做法 | 说明 | 安全性 |
|---|---|---|
| **VPN**（推荐） | 院里通常已有 VPN，让需要的人拨进来即可，无需改动系统 | 高 |
| 端口映射 | 在出口防火墙把 443 映射到内网服务器 | 中，需 HTTPS + 建议限制来源 |
| 迁到公网 | 把 `data` 目录整个搬到云服务器 | 见《部署手册.md》 |

> 数据不出院区是内网方案的核心价值，做端口映射前请先和信息科确认是否符合院内规定。

## 九、备份（内网同样不能省）⚠

内网服务器**更容易被忽视备份**——毕竟"就在楼下"。但硬盘坏了、误删了，一样全没。

- 自动备份已配置：每天 02:30 自动备份到服务器 `data/backups/`，保留 30 天
- ⚠ **但备份和数据在同一块硬盘上**，硬盘坏了两边一起丢

**必须做的**：每周固定时间把备份拷到**另一台机器或移动硬盘**（详见《运维手册.md》第 1 节）。

- [ ] 定好责任人：`________________`
- [ ] 定好时间：建议每周一上午
- [ ] 定好存放位置（另一台电脑 / 移动硬盘 / 院内文件服务器）
- [ ] ⚠ 上线第一周做一次**恢复演练**（《运维手册.md》第 3 节）

> 若院内有备份系统（如虚机快照），也请让网管把这台服务器纳入。
> 虚机快照 + 每周下载，双保险最稳。
