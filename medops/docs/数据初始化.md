# 数据初始化 —— 上线前把基础数据一次建好

> 读者：设备科系统管理员。前提：系统已部署完成，能用管理员账号登录后台：
>
> - 局域网部署：`http://服务器IP/admin/`（如 `http://192.168.1.50/admin/`）
> - 公网部署：`https://你的域名/admin/`
>
> 下文统称"后台"。
>
> 建议按本文顺序操作：**建科室 → 导设备 → 开账号 → 录签字人 →（可选）迁移试用期数据**。
> 全部完成后即可发二维码给科室正式使用。

---

## 1. 建科室

后台左侧菜单 **「科室管理」→「+ 新建科室」**，逐个录入参与巡检的科室：

| 字段 | 说明 |
|---|---|
| 名称 | 科室全称，如 `急诊科`。**后面 Excel 导入设备时要按这个名称精确匹配，建议一次定稿** |
| 编码 | 院内科室编号，可留空 |
| 排序 | 数字越小排越前，控制 H5 里科室列表顺序 |

> 科室建错了怎么办：还没有巡检记录的科室可以直接删除；已产生记录的只能"停用"，
> 停用后 H5 不再显示，历史数据保留。

## 2. 下载设备导入模板

后台 **「设备台账」** 页，点右上角 **「下载导入模板」**，得到 `设备导入模板.xlsx`。

> 也可以直接用发给你的 **《数据准备模板》里的 `2-设备表.xlsx`**（内容一致，且带填写说明和查重提示）。

**模板有两张表**：

| 工作表 | 用途 |
|---|---|
| **第 1 张「设备导入」** | ← **填这里**。只有表头，从第 2 行开始录数据 |
| 第 2 张「填写示例」 | 只是给你看的参照，**系统导入不会读它**，不用删 |

> 设备少（几十台以内）也可以不走 Excel，直接在「设备台账」页逐台「新增」，字段含义同下表。

## 3. Excel 填写规范

模板共 7 列，**从第 2 行开始填数据（第 1 行表头不要动，列的顺序不要调整）**：

| 列 | 是否必填 | 填写说明 |
|---|---|---|
| 科室名称 | 必填 | 必须与第 1 步建的科室**名称完全一致**（一个字都不能差，注意别混入空格） |
| 设备品类 | 必填 | 大类名称，如 `除颤仪`、`心电监护仪`、`吸引器`、`简易呼吸器`。H5 里按品类分组显示，同类设备写法要统一 |
| 设备编码 | 必填 | 院内资产编号，如 `JJ-ECG-001`。**全院唯一**；重复导入同一编码=更新该设备信息（不会产生重复设备） |
| 设备名称 | 必填 | 具体名称，如 `飞利浦除颤监护仪` |
| 型号 | 选填 | 如 `HeartStart XL+` |
| 位置 | 选填 | 摆放位置，如 `抢救室急救车`。巡检时显示，建议填写 |
| 状态 | 选填 | 只能填 `在用` / `维修` / `停用` / `报废` 四种之一，留空默认 `在用`。只有"在用"设备出现在巡检清单里 |

示例行：

| 科室名称 | 设备品类 | 设备编码 | 设备名称 | 型号 | 位置 | 状态 |
|---|---|---|---|---|---|---|
| 急诊科 | 除颤仪 | JJ-CCY-001 | 飞利浦除颤监护仪 | HeartStart XL+ | 抢救室急救车 | 在用 |
| 急诊科 | 心电监护仪 | JJ-JHY-003 | 迈瑞心电监护仪 | uMEC12 | 抢救室 2 床旁 | 在用 |
| ICU | 简易呼吸器 | ICU-HXQ-007 | 球囊面罩复苏器 |  | 治疗室壁柜 | 在用 |

## 4. 导入

后台 **「设备台账」→「批量导入」**，选择填好的 xlsx（5MB 以内），点 **「开始导入」**。

导入结果会显示 新增 X 台 / 更新 X 台，以及**逐行错误清单**。常见错误：

| 提示 | 处理 |
|---|---|
| `科室「xxx」不存在` | Excel 里的科室名称和后台建的不一致（错字/空格），改一致后**整个文件重新导入即可**（已成功的行会按编码更新，不会重复） |
| `科室名称/设备品类/设备编码/设备名称不能为空` | 补齐该行必填列后重新导入 |

导入完成后在「设备台账」页按科室筛选抽查几台，确认信息无误。

## 5. 建账号

后台 **「账号管理」→「+ 新建账号」**。三种业务角色对应三份培训材料，开号时按人对号入座：

| 角色 | 给谁 | 数据范围 | 对应培训材料 |
|---|---|---|---|
| 巡检员 | 各科室做日常巡检的护士/技师 | 可勾选**多个**负责科室；做日检打勾、异常备注、每日签名 | 《培训材料-巡检员.md》 |
| 护士长 | 每科室 1 名 | **单个**科室；每周核查后完成周签 | 《培训材料-护士长.md》 |
| 设备科 | 设备科管理人员 | **全院**；月度核查月签、统计导出、台账维护，可登录本后台 | 《培训材料-设备科.md》 |
| 超级管理员 | 系统管理员本人 | 全院全部功能 + 账号管理、签字作废、历史数据导入 | —— |

填写建议：

- 登录账号：用工号或姓名全拼，如 `hs_liuyan`，只含字母数字，方便口头传达；
- 初始密码：设置后当面告知本人。护士长/设备科可在后台右上角「修改密码」自行更换；巡检员需要换密码时由管理员「重置密码」处理；
- 姓名：填真实姓名，签字和统计里都显示它；
- 忘记密码：管理员在「账号管理」点该账号的 **「重置密码」**，系统生成一次性密码，只显示一次，当场告知本人，其首次登录会强制改密；
- 人员离职：把账号 **停用**（不要删除），停用立即踢下线，历史签名记录保留。

## 6. 录签字人名单

后台 **「签字人名单」**：按科室维护"允许在巡检单上签名的人"（H5 里签字时从这份名单里选人，
再手写签名）。每个科室至少录入：全部巡检员 + 护士长，字段为 姓名、职称（如 `主管护师`）。

> 签字人名单和登录账号是两回事：名单解决"签字栏里显示谁、职称是什么"，
> 账号解决"谁能登录系统"。人员变动时两边都要维护。

## 7. H5 试用期数据迁移（可选，仅超级管理员）

试用阶段用的旧版 H5 把数据存在**当时使用的那个浏览器**里（localStorage）。
若希望正式系统延续这些历史记录，按下述步骤迁移；若决定从零开始，跳过本节即可。

**第一步：从旧浏览器导出 JSON**

1. 在**试用时使用的那台电脑、那个浏览器**里打开旧版 H5 页面；
2. 按 `F12` 打开开发者工具，切到 **Console（控制台）** 页签；
3. 粘贴下面整段代码后回车，浏览器会下载 `xunjian-export.json`：

```js
(function () {
  var ks = ['depts', 'devices', 'members', 'users', 'records', 'weeksigns', 'monthsigns'];
  var out = {};
  ks.forEach(function (k) { out[k] = JSON.parse(localStorage.getItem('insp:' + k) || '[]'); });
  var a = document.createElement('a');
  a.href = URL.createObjectURL(new Blob([JSON.stringify(out)], { type: 'application/json' }));
  a.download = 'xunjian-export.json';
  a.click();
})();
```

> 粘贴时若控制台提示需要先输入 `allow pasting`，照做后再粘贴。
> 试用数据在手机浏览器里的话：安卓手机可用数据线连电脑，在电脑 Chrome 打开
> `chrome://inspect` 远程调试手机页面后同样执行；不具备条件且数据量不大时，建议放弃迁移、正式系统从头记录。

**第二步：导入到正式系统**

1. 用超级管理员登录后台，左侧菜单 **「历史数据导入」**；
2. 点「选择 .json 文件」上传刚导出的文件（或直接把文件内容粘贴进文本框）；
3. 核对页面显示的各类数据条数（科室/设备/签字人/账号/日巡检记录/周签/月签）；
4. 点 **「开始导入」**。导入是一次性事务：同名科室与同编码设备自动合并，不会重复。

**第三步：导入后必做**

- 旧数据里的**账号密码全部被重置为随机值**（安全要求）：在「账号管理」逐个点「重置密码」，
  把一次性密码告知本人；
- 抽查历史记录：打开「巡检记录」选试用期的日期，确认打勾与签名图都在；
- 若第 1～6 节已建过部分数据，检查有无重复科室（名称不同会各建一个），多余的停用即可。
