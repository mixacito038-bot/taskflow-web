# 局域网电脑部署指南 —— 用一台自己的电脑当服务器

> 适用场景：不买云服务器、不用域名，把系统装在**院内（或办公室内）的一台电脑**上，
> 同一个局域网里的手机和其他电脑都能访问。数据全部留在这台电脑上，不出院区。
>
> 全程约 30～60 分钟，绝大部分时间在等下载。

---

## 一、先准备这台电脑

### 硬件要求（很低）

| 项 | 要求 |
|---|---|
| CPU / 内存 | 2 核 / 4GB 以上 |
| 硬盘剩余 | 20GB 以上 |
| 系统 | Windows 10/11 专业版或家庭版、macOS、Ubuntu 都行 |

### ⚠ 三个必须满足的条件

- [ ] **能一直开机不关**——这台电脑关了，全院就都用不了了
- [ ] **不是某个人正在办公的电脑**——他一关机、一休眠，系统就断
- [ ] **插在有市电保障的插座上**，最好接 UPS（突然断电可能损坏数据库）

### ⚠ 关掉睡眠（Mac 用户尤其注意）

**电脑一睡眠，等于全院断服。** 按系统分别设置：

**Windows**
设置 → 系统 → 电源 → 屏幕和睡眠 → **睡眠时间全部设为「从不」**。

**macOS（台式：Mac mini / iMac / Mac Studio）**
系统设置 → 节能（或「锁定屏幕」）→ 勾选 **「防止电脑自动进入睡眠」**，
把「无活动时关闭显示器」之外的睡眠项都关掉。

**macOS（笔记本：MacBook）** ⚠ 最容易踩坑
MacBook **合上盖子就会睡眠**，服务立刻中断。三选一：

1. **别合盖**，把屏幕亮度调到最低即可（最省事）
2. 接上电源 + 外接显示器/键鼠，用「合盖不休眠」模式
3. 终端执行下面这条命令，彻底禁用睡眠（需要输入开机密码）：

```
sudo pmset -a disablesleep 1
```

> 恢复默认：`sudo pmset -a disablesleep 0`
> 查看当前设置：`pmset -g`

**说实话**：MacBook 长期当服务器不太合适（合盖、电池、误带走）。
如果有 Mac mini 或一台台式机，优先用那个。

## 二、⚠ 把这台电脑的 IP 固定下来

**这是整个部署里最容易翻车的一步。**

手机扫的二维码里写死的是这台电脑的 IP。如果 IP 会变，电脑一重启，
**全院贴出去的二维码就全部失效**，得重印重贴。

### 怎么做（二选一，找网管或懂路由器的人帮忙）

**方法 A：在路由器里做「IP/MAC 绑定」（推荐）**
登录路由器管理页 → 找到「DHCP 静态地址分配」或「地址保留」→ 把这台电脑的 MAC 地址绑定到一个固定 IP。

**方法 B：在电脑上设静态 IP**

- **Windows**：设置 → 网络和 Internet → 以太网 → IP 分配 → 编辑 → 手动 → 打开 IPv4，
  填 IP（如 `192.168.1.50`）、子网掩码、网关、DNS
- **macOS**：系统设置 → 网络 → 选中正在用的网络（Wi-Fi 或以太网）→ 详细信息 →
  TCP/IP → 「配置 IPv4」改为 **「手动」** → 填 IP、子网掩码、路由器地址

**填之前先问网管要一个没人用的 IP**，否则可能和别的设备撞号。

### 查当前 IP

- **Windows**：`Win + R` 输入 `cmd` 回车，执行 `ipconfig`，看「IPv4 地址」
- **macOS**：系统设置 → 网络 → 详细信息 → TCP/IP；或在终端执行：

```
ipconfig getifaddr en0
```

> 上面这条查的是 Wi-Fi。如果这台 Mac 插的是**网线**，改用这条自动识别：
> `ipconfig getifaddr $(route -n get default | awk '/interface:/{print $2}')`
> （部署脚本跑完也会直接把 IP 打印出来，不用自己查。）

## 三、装 Docker Desktop

打开 [https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/)，
下载对应系统的版本，一路下一步装完（Windows 首次会要求重启电脑）。

装好后**启动它**，等右下角的鲸鱼图标不再转动、显示 running 即可。

### ⚠ 一定要打开「开机自启动」

Docker Desktop → 右上角齿轮（Settings）→ General → 勾选
**Start Docker Desktop when you sign in to your computer**。

不勾的话，电脑重启后系统不会自己起来，得有人手动开。

## 四、放代码并部署

### 1. 解压

把压缩包解压，得到 `medops` 文件夹，放在**不会被误删**的位置：

| 系统 | 建议放这里 | 别放这里 |
|---|---|---|
| Windows | `D:\medops` | 桌面、下载文件夹 |
| **macOS** | **`~/medops`（个人文件夹下，如 `/Users/你的用户名/medops`）** | ⚠ **`/opt`、`/srv` 等系统目录** |
| Linux | `/opt/medops` | — |

> ⚠ **macOS 特别注意**：Docker Desktop for Mac 默认只允许挂载
> `/Users`、`/Volumes`、`/private`、`/tmp` 这几个位置。
> 放在 `/opt` 下会报挂载失败。**放个人文件夹（`~`）下最省事。**
> （非要放别处的话：Docker Desktop → Settings → Resources → File sharing 里手动加上该目录。）

> 解压后**同级**会自动生成一个 `data` 文件夹存放数据
> （如 `D:\data` 或 `/Users/你的用户名/data`），**这个文件夹就是全部家当，别删。**

### 2. 运行一键部署

**Windows：**

进入 `medops\deploy\local` 文件夹，**右键点「一键部署.bat」→ 以管理员身份运行**。

> 为什么要管理员？为了自动放行 Windows 防火墙，否则手机连不上。
> 不用管理员也能装，只是防火墙要你自己手动开。

**macOS / Linux：**

打开「终端」（macOS：聚焦搜索输入「终端」回车），执行：

```
cd ~/medops/deploy/local
bash setup.sh
```

> 小技巧：在访达里进到 `local` 文件夹，右键 →「服务」→「新建位于文件夹位置的终端窗口」，
> 就不用手敲路径了，直接输 `bash setup.sh` 即可。

### 3. 按提示操作

脚本会依次做这些事，你只需要在第 4 步输入内容：

| 步骤 | 脚本做什么 | 你要做什么 |
|---|---|---|
| 1 | 生成随机密钥写入 `.env` | 等着 |
| 2 | 创建数据目录 | 等着 |
| 3 | 构建后端镜像并启动 | **等 3～5 分钟**（首次要下载，慢） |
| 4 | 创建管理员账号 | **输入账号（建议 admin）和密码（至少 6 位）** |
| 5 | 启动网页服务 | 等着 |
| 6 | 放行防火墙（仅 Windows） | 等着 |

> 输密码时**屏幕上不会显示任何字符**（连星号都没有），这是正常的，照打然后回车即可。

结束后屏幕会打印访问地址，**把它抄下来**。

### macOS 上的防火墙

macOS 防火墙默认是**关闭**的，通常不用管。如果你开了防火墙，
第一次启动时系统会弹窗问「是否允许 Docker 接受传入网络连接」，**点「允许」**。

误点了「拒绝」的话：系统设置 → 网络 → 防火墙 → 选项 → 找到 Docker，改成「允许传入连接」。

## 五、验收：五件事都做一遍

### 1. 在这台电脑上打开

浏览器输入 `http://localhost/`，应该看到入口页。

### 2. 用另一台电脑打开

同一局域网的电脑输入 `http://这台电脑的IP/`（如 `http://192.168.1.50/`）。

打不开的话看第七节「手机/其他电脑连不上」。

### 3. 用手机打开

手机连**同一个 WiFi**，浏览器输入同样的地址。再用**微信扫一扫**试一次。

### 4. 登录管理后台

`http://192.168.1.50/admin/`，用刚创建的管理员账号登录。

### 5. 检查服务器时间 ⚠

登录后看首页右上角的「服务器时间」，**必须等于当前北京时间**。

不对的话，先把这台电脑的系统时间调准（Windows：设置 → 时间和语言 → 自动设置时间），
然后在 `medops\deploy\local` 目录执行 `docker compose restart`。

> 三级签字的"今天是哪天"全靠服务器时间裁决，时间错了签字日期就全错，且很难发现。

## 六、日常操作速查

所有命令都在 `medops\deploy\local` 目录下执行
（Windows 在该文件夹地址栏输入 `cmd` 回车即可打开命令行）。

| 想做什么 | 命令 |
|---|---|
| 看运行状态 | `docker compose ps` |
| 看后端日志 | `docker compose logs -f api` |
| 重启 | `docker compose restart` |
| 停止 | `docker compose down` |
| 启动 | `docker compose up -d` |
| 重置管理员密码 | `docker compose run --rm api node src/scripts/create-admin.js admin 新密码` |

> 电脑重启后，只要 Docker Desktop 开机自启，系统会自动恢复，不用手动执行任何命令。

## 七、常见问题

| 现象 | 处理 |
|---|---|
| **提示 Docker 没有在运行** | 先启动 Docker Desktop，等鲸鱼图标不转了再重跑脚本 |
| **提示端口被占用** | 打开 `deploy/local/.env`（Win 用记事本，Mac 用文本编辑），把 `WEB_PORT=80` 改成 `WEB_PORT=8080`，重跑脚本。之后地址变成 `http://192.168.1.50:8080/` |
| **手机/其他电脑连不上** | ① 确认手机连的是**同一个 WiFi**；② Windows：右键「一键部署.bat」用管理员身份重跑一次放行防火墙；macOS：系统设置 → 网络 → 防火墙里允许 Docker；③ 让网管确认手机所在网段能访问服务器网段（有些医院 WiFi 分段隔离） |
| **本机能开，别人不能开** | 基本都是防火墙或网段隔离，见上一条 |
| **重启电脑后打不开** | 检查 Docker Desktop 是否开机自启（第三节）；启动后等 1～2 分钟 |
| **睡一觉起来打不开（Mac）** | 电脑睡眠了，见第一节「关掉睡眠」 |
| **IP 变了，二维码全失效** | 说明 IP 没固定，回第二节处理，然后重新生成二维码 |
| **构建时报网络错误** | 换个网络重试；公司网有代理的话在 Docker Desktop → Settings → Resources → Proxies 里填 |
| **Mac 报 mounts denied / 挂载失败** | medops 放到了 Docker 不共享的目录。移到个人文件夹下（`~/medops`）重跑；或在 Docker Desktop → Settings → Resources → File sharing 里把该目录加进去 |
| **Mac 提示 permission denied** | 在 `deploy/local` 目录执行 `chmod +x setup.sh` 后重跑；或直接用 `bash setup.sh` |
| **想从零重来** | `docker compose down`，删掉 `data` 文件夹，重跑脚本 |

## 八、⚠ 备份（不能省）

自动备份每天凌晨 02:30 生成，存在 `data/backups/` 里，保留 30 天。
**但它和数据在同一块硬盘上——这台电脑坏了，两边一起没。**

### 必须做的

每周固定时间，把整个 `data` 文件夹复制到**另一台电脑或移动硬盘**。

- Windows：直接复制 `D:\data` 文件夹
- macOS：在访达里复制 `data` 文件夹（在你的个人文件夹下），或用终端：

```
cp -R ~/data ~/Desktop/巡检备份-$(date +%Y%m%d)
```

- [ ] 责任人：`________________`
- [ ] 时间：建议每周一上午
- [ ] 存放位置：`________________`

### 怎么恢复（已实测验证）

新电脑上装好 Docker、解压 medops、把备份的 `data` 文件夹放回**与 medops 同级**的位置，
再跑一次部署脚本即可——科室、设备、账号、签字记录会原样回来。

> **上线第一周务必演练一次恢复**，不然备份等于没有。详见《运维手册.md》第 3 节。

## 九、和公网部署的区别（心里有数）

| | 这个方案（局域网） | 公网（腾讯云） |
|---|---|---|
| 手机在哪能用 | **只有连院内 WiFi 时** | 任何地方（4G/5G/家里） |
| 护士长在家补签 | 不行 | 可以 |
| 数据存在哪 | **这台电脑，不出院区** | 腾讯云机房 |
| 备案 | **不需要** | 需要，1～2 周 |
| 费用 | **0 元** | 约 1000～2000 元/年 |
| 网页加密 | 无（HTTP） | 有（HTTPS 绿锁） |
| 断外网 | **不影响** | 全院用不了 |

### 关于「没有 HTTPS」

局域网内是明文传输，密码理论上可被同网段的人抓包看到。实际风险要看你们的网络环境：

- 一般院内网络、人员可控 → 可以接受，先用起来
- 院里有**等保测评**要求，或不放心 → 有两条路：
  1. 你已经有域名，可以用「DNS 验证 + 院内解析」的方式拿一张正规证书，
     手机上照样是绿锁——具体见《内网部署方案.md》第四节方案 B，需要网管配合
  2. 改成公网部署

需要走 HTTPS 的话告诉我，我把配置和步骤给你。
