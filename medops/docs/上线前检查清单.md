# 上线前检查清单

> 从"决定要上"到"全院开始用"，照着这张表逐条打勾即可。
> 方框 `[ ]` 打勾 `[x]` 表示完成。**带 ⚠ 的是最容易卡住或返工的环节，务必提前办。**
>
> 全表分五段：A 提前两周办 → B 数据准备 → C 院内决定 → D 部署当天 → E 上线后一周。

---

## A. 提前两周就要开始办 ⚠

这两件事不办完，后面所有步骤都白搭，且都需要等待时间。

### A1 ⚠ 确认备案"接入"在哪一家

域名已备案 **不等于** 能直接用在腾讯云的服务器上。备案分"主体备案"和"接入备案"——
换云服务商必须重新办接入，还要 1～2 周。

- [ ] 登录腾讯云控制台，搜索"备案"，查询自己的域名
- [ ] 能查到 → 接入已在腾讯云，**无需等待**，跳到 A2
- [ ] 查不到 → 接入在别家（阿里云/华为云等），需办 **接入备案**，现在就提交
- [ ] 不想等 → 服务器地域改选 **香港**（免备案，其余步骤完全一样）

> 内网部署（服务器放在院内）**完全不需要备案**。见《内网部署方案.md》。

### A2 ⚠ 定死设备编码规则

设备编码是系统里的唯一身份证，靠它判断"新增还是更新"。一旦开始积累巡检记录，
再改编码等于换了一台新设备，历史记录会对不上。

- [ ] 全院统一一套规则，建议 `科室简码-品类简码-序号`，例：`JZ-CD-01`（急诊科-除颤仪-01）
- [ ] 简码表先定好并发给各科室（避免有人写 `JZ` 有人写 `JZJ`）
- [ ] 序号留够位数（超过 9 台的品类用两位）
- [ ] 明确一条：**编码一经录入不再更改**

### A3 决定部署方式

- [ ] 公网部署（腾讯云）→ 走《部署手册.md》
- [ ] 内网部署（院内服务器）→ 走《内网部署方案.md》

两者对比见《内网部署方案.md》开头的表格。**数据不出院区**是内网的最大优势。

## B. 数据准备（可与 A 并行，现在就能让各科室开始报）

三张表用《数据准备模板》里的 Excel 填，表内有填写说明页。

- [ ] **科室表**：科室名称、简码、排序
- [ ] **设备表**（大头）：科室 / 品类 / 编码 / 名称 / 型号 / 存放位置 / 状态 / 有效期 / 提醒提前天数
  - [ ] 各科室护士长上报，设备科汇总去重
  - [ ] 编码按 A2 的规则统一检查一遍，**不能有重复**
  - [ ] 科室名称必须与科室表**完全一致**（差一个字导入就会报错）
  - [ ] **有效期**：至少把「除颤电极片」和「急救药品」两类的到期日报上来
        （格式 `2027-03-15`；监护仪、呼吸机等设备本体没有有效期，留空）
        —— 这是防"抢救时才发现过期"的唯一一道关，上线时一起录进去，别留到以后补
- [ ] **人员表**：姓名 / 角色 / 负责科室 / 建议账号名
  - [ ] 巡检员：可管多个科室
  - [ ] 护士长（科室角色）：一人对一个科室
  - [ ] 设备科：全院范围
- [ ] **签字人名单**（含在人员表里）：每科室能签周签的人，通常是护士长、副护士长

> 设备表可以先报个大概，上线后随时能在后台增改，或再导一次 Excel（同编码自动更新）。

## C. 院内需要拍板的事（技术之外，但决定项目成败）

- [ ] **电子签名院里认不认？**
      质控、院感、等级评审时是否仍要纸质原件？
      若要 → 用系统导出月报打印后手签，变成"系统 + 纸质"双轨，流程要先讲清楚。
- [ ] **谁当系统管理员？**
      管理员能看全院数据、能作废任何签字。建议给设备科负责人，**密码单独保管，不与日常账号混用**。
- [ ] **切换时点定在月初** ⚠
      三级签字按周、月结算。月中切换会导致这个月数据一半在旧记录、一半在新系统，月签凑不齐、设备科签不了字。
      建议定在某月 1 号 0 点切换。
- [ ] **先试点再铺开**
      建议先选 1 个科室试用两周，跑顺了再全院推。系统再好，一线不用就白搭。
- [ ] **旧数据要不要迁？**
      手机端试用期录的数据可在后台「历史数据导入」一次性迁入。决定迁 → 在切换当天做。
- [ ] **培训安排**
      巡检员、护士长各讲一次（各 15 分钟够了）；二维码贴在各科室抢救车/护士站。

## D. 部署当天

### D1 装好系统

- [ ] 按《腾讯云部署指南.md》（端口 8912，一键脚本）完成部署
      —— 要 HTTPS + 域名 + 免费证书的完整版看《部署手册.md》；纯内网看《内网部署方案.md》
- [ ] ⭐ **腾讯云安全组已放行 8912 端口**（网页控制台操作，最容易漏；
      症状是"服务器上自检全过、浏览器一直转圈"）
- [ ] `bash deploy.sh` 最后的七项自检全部打勾
- [ ] 浏览器能打开 4 个地址：入口页 / `/xunjian/` / `/admin/` / `/pandian/`
- [ ] 手机**用 4G（不连院内 WiFi）**能打开 `/xunjian/`，微信扫码也能打开
- [ ] 少打斜杠也能进：`http://IP:8912/admin`（无尾斜杠）应能正常跳转，端口号不丢
- [ ] 公网部署且已上 HTTPS：地址栏显示 **绿锁**
      （只开 8912 走 http 时没有绿锁，属预期；密码明文传输的风险见《腾讯云部署指南.md》第 0 节）

### D2 ⚠ 校准服务器时间

整套三级签字的"今天是哪天"全部由服务器裁决。服务器时间错 → 签字日期全错。

- [ ] 在服务器上执行 `date`，确认日期正确
- [ ] 登录管理后台首页，右上角"服务器时间"显示的应是**当前北京时间**
- [ ] 内网部署额外确认 NTP 时间同步可用（详见《内网部署方案.md》）

### D3 建数据

- [ ] 管理员账号与密码已设好
      （安装脚本 `first-run.sh` 第 5 步会当场让你输入，**没有默认密码**；
      本地试跑版才是 `admin/admin123`）
- [ ] 「科室管理」按科室表建科室
- [ ] 「设备台账 → 下载导入模板」，把设备表内容填进模板**第 1 张表**后上传
      （模板第 2 张表是填写示例，不会被导入）
- [ ] 导入后核对：设备总数对不对、有没有报错行
- [ ] 后台首页看一眼「有效期提醒」卡片：已过期的当天安排更换，临期的备好替换件
      （没有临期项时卡片不显示，属正常）
- [ ] 「签字人名单」按科室录入护士长
- [ ] 「账号管理」建账号，分配角色和科室范围
- [ ] 把初始密码分别告知本人，并叮嘱首次登录后自行修改
      （新建账号**不会**强制改密；若想强制，建完账号后再点一次「重置密码」，
      系统会生成一次性密码并置为"首次登录必须改密"）

### D4 走一遍真实流程再宣布上线

- [ ] 用巡检员账号在**手机上**登录，完成一次日签（手写签名能签上）
- [ ] 用护士长账号完成一次周签（确认日签没齐时会被拦住）
- [ ] 用设备科账号试月签（确认有周没签时会被拦住）
- [ ] 在管理后台导出一次月报 xlsx，打开确认签名图在里面
- [ ] 用**微信**扫二维码打开 `/xunjian/`，确认能正常显示和登录
- [ ] 随便挑一台设备，把有效期临时改成明天，确认手机首页出现黄色「还剩 1 天」，改回后提醒消失

### D5 二维码上墙

- [ ] 用草料二维码等工具把 `/xunjian/` 地址生成二维码
- [ ] 打印后贴到各科室抢救车、护士站
- [ ] 二维码旁写一行字：**扫码 → 登录 → 今日巡检**

## E. 上线后第一周

- [ ] ⚠ **做一次恢复演练**（《运维手册.md》第 3 节）——不演练的备份等于没有备份
- [ ] ⚠ **下载一次备份到院内电脑**（《运维手册.md》第 1 节）
      自动备份和数据在同一台机器上，机器整个坏了两边一起没
- [ ] 定好每周固定下载备份的时间（建议每周一上午）和责任人
- [ ] 把《运维手册.md》第 8 节"服务器故障应急预案"讲给护士长听
      （**核心一句：打不开就先记纸上，恢复后能补签**）
- [ ] 观察一周完成率，对没签的科室点对点提醒

### 上线三个月后（设个日历提醒）

- [ ] 公网部署：看一眼地址栏还是不是绿锁（证书 90 天自动续期，万一续失败要及时发现）
- [ ] 看一眼磁盘占用：`df -h`

## 常见返工点排行（前人踩过的坑）

| 排名 | 坑 | 后果 | 预防 |
|---|---|---|---|
| 1 | 备案接入没提前办 | 上线整体推迟 1～2 周 | A1 |
| 2 | 设备编码没统一 | 导入报错或重复设备，返工重导 | A2 |
| 3 | 月中切换 | 首月月签凑不齐，设备科签不了 | C |
| 4 | 服务器时间不准 | 签字日期错位，且不易察觉 | D2 |
| 5 | 科室名称不一致 | 设备导入整行失败 | B |
| 6 | 从不下载备份 | 服务器故障时数据全丢 | E |
| 7 | 没试点直接全院推 | 一线抵触，项目停摆 | C |
