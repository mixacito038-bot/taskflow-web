## 二、功能盘点（逐菜单结论）

### 保留并已增强
| 菜单/模块 | 结论 | 本轮动作 |
|---|---|---|
| 效益驾驶舱 | 核心 | 新增拖拽布局编辑（宽/高/顺序，按医院保存） |
| 采集与分析 | 核心 | 新增「全面监测」页签（第一个专业分析模板） |
| 医院与权限 | 核心 | 账号分配/重置密码、角色按菜单勾选 |

| 个人中心 | 保留 | 新增修改密码；文案去网关化 |

### 保留、建议后续深化（按优先级）
| 模块 | 建议 | 理由 |
|---|---|---|
| 效益分析报告 | **P0：一键月度报告**——选医院+月份自动出草稿（模板已具备，缺一个快捷入口）；报告归档列表加检索 | 行业调研结论：医院最愿意为"自动出报告替代手工拼 Excel"付费 |
| 运营改进中心 | **P1：预警→改进自动化**——阈值规则可配置（利用率<55%、回收期>8年、停机>72h 自动生成待办建议，负责人一键认领） | 现在预警和改进任务是两步手工衔接；阿基米德"报告—原因—行动"链路是对标点 |
| 设备台账 | **P1：单机档案页强化**——设备二维码（扫码直达单机页）、采购/使用/维修/收入在同一时间轴 | 借鉴康医通/Shelf：现场工程师和科室主任都从"一台设备"进入系统 |
| 资本计划 | 保留 | 3—5 年更新替换建议是院长层的决策抓手，行业稀缺能力，不要删 |
| 消息中心 | **P1：统一预警中心**——把数据质量、维保到期、效益预警、报告待办统一成可配置订阅 | 现在消息是静态样例为主 |
| 成本填报 | 保留，建议与数据准备中心的 cost_detail 模板打通（填报=生成一个人工来源批次） | 消除"两套成本入口"的口径分叉 |
| 驾驶舱 | **P2：投屏大屏模式**——一键全屏、隐藏侧栏、自动轮播模块，配合已有布局编辑即是"数据大屏" | 你提到的"大屏"场景，改动小价值高 |

## 三、数据从"示范"到"真实"的路径（重要）

现在系统里有三层数据，边界清晰：
1. **体验数据**（未登录）：~20 台设备、12 个月经营数据，只存浏览器，重在"看起来是真的"。
2. **示范数据包**（数据准备中心可下载）：8 类相互勾稽的业务文件（设备台账/检查/收费/成本/维修/利用/质量/目标），可完整走一遍 导入→映射→清洗→复核→发布，发布后正式模式即显示"真数据"。
3. **医院真实数据**：拿医院导出的 Excel 按同样流程进；指标经审核激活后进入驾驶舱与报告。

**建议的演示准备动作**：用示范数据包在一个正式账号下走完一次发布，这样"正式模式"也有数据可看（目前正式模式无发布版本时如实显示空态，这是刻意的诚实设计，不建议改）。

## 四、暂不建议做的事

1. **不建议现在做 HIS/PACS 在线对接**——文件链路已闭环，接口留待医院给出测试环境再做（模型已预留）。
2. **不建议把演示模式删掉**——销售现场没网/没账号时它是保底；已把话术从"演示"弱化为"体验"。
3. **不建议在前端放开任意公式脚本**——公式引擎故意只支持四则运算，防注入也防口径失控；复杂指标应走"新建指标+审核激活"。
4. **不建议直接上生产**——腾讯云 Node/MySQL/COS 适配与等保项未做（迁移包文档已列清单），当前形态适合演示与试点验证。
