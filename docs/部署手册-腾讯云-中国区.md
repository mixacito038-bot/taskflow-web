# 勇虹医疗设备效益管理平台 · 部署手册（腾讯云 / 中国大陆）

适用环境：**TencentOS Server 4 · x86_64**（CentOS 8 / Anolis / 麒麟同理）。
交付形态：**源码包 + 构建产物**，上传后即可运行。

> 一句话结论：包内已含构建产物 `dist/`，院内服务器**不需要外网、不需要 npm install、不需要拉任何 npm 依赖**。
> 唯一可能需要联网的只有"装 Node 22"或"拉 Docker 基础镜像"这一步，二者都给了国内源。

---

## 零、先确认三件事（中国大陆特有）

| 事项 | 说明 |
|---|---|
| **ICP 备案** | 大陆服务器对公网开放 80/443 前，域名必须完成 ICP 备案，否则腾讯云会拦截。备案期间可先走内网 IP 试用（见"试用模式"），**不要用非标端口绕开**。 |
| **安全组** | 只放行 `22`（SSH）与 `443`（HTTPS）。应用端口 `8911` **不要**对公网开放——两种部署方式都默认只监听 `127.0.0.1`。 |
| **HTTPS 证书** | 腾讯云 SSL 证书控制台可申请免费 DV 证书，下载 Nginx 格式即可。**不建议用 certbot/Let's Encrypt**：国内续期常因网络失败，到期就是全院登录不上。 |

平台本身**零外网依赖**：前端资源全部由本进程直出，无 CDN、无 Google Fonts、无外部字体与统计脚本。
断网环境下功能完整（已实测）。唯一的外链是运营改进中心里三条"官方来源"参考资料（国家卫健委 / WHO / NHS），
点击才访问，不点不影响任何功能。

## 二、部署方式 A：免 Docker（推荐，最省事）

```bash
bash deploy/install-tencentos.sh
```

脚本会自动完成：装 Node 22（缺才装）→ 建 `yonghong` 服务账号 → 部署到 `/opt/yonghong-platform`
→ 生成 `/etc/yonghong-platform.env`（**随机初始管理员密码**）→ 注册 systemd 服务 → 健康自检。
结束时会打印管理员账号、初始密码与数据准备中心入口口令。

```bash
systemctl status yonghong-platform          # 运行状态
journalctl -u yonghong-platform -f          # 实时日志
curl http://127.0.0.1:8911/healthz          # {"ok":true}
```

数据全部在 `/var/lib/yonghong-platform`（SQLite + 上传文件 + 报告），备份这一个目录即可。

### 若服务器完全没有外网（连 Node 都装不了）

在任意一台能上网的同架构机器上下载 Node 22 的 Linux x64 二进制包，
解压到 `/usr/local/node22` 并 `ln -s /usr/local/node22/bin/node /usr/bin/node`，再跑上面的脚本。
国内下载地址：`https://registry.npmmirror.com/-/binary/node/latest-v22.x/node-v22.x.x-linux-x64.tar.xz`

## 三、部署方式 B：Docker 编排

```bash
# 1) 装 Docker（TencentOS 4 兼容 el9 源）
dnf install -y dnf-utils
dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
dnf install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 2) 配镜像加速（国内直连 Docker Hub 不稳定）
cat > /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://mirror.ccs.tencentyun.com"] }
EOF
systemctl enable --now docker && systemctl restart docker

# 3) 配置并启动
cp .env.tencent.docker.example .env
vi .env                       # 改管理员密码、入口口令；TZ 已默认 Asia/Shanghai
docker compose -f docker-compose.tencent.yml up -d
docker compose -f docker-compose.tencent.yml ps        # STATUS 应为 healthy
```

镜像加速仍拉不动时，直接换成腾讯云的官方镜像副本（CVM 内网走，免流量）：

```bash
echo 'BASE_IMAGE=ccr.ccs.tencentyun.com/library/node:22-bookworm-slim' >> .env
docker compose -f docker-compose.tencent.yml build --no-cache && docker compose -f docker-compose.tencent.yml up -d
```

数据在命名卷 `yonghong-data`，纳入快照策略即可。

## 四、nginx + HTTPS（正式使用必做）

```bash
dnf install -y nginx
mkdir -p /etc/nginx/certs        # 放腾讯云下载的 fullchain.crt / privkey.key
cp tencent-cloud/nginx.conf.example /etc/nginx/conf.d/yonghong.conf
vi /etc/nginx/conf.d/yonghong.conf     # 改 server_name 与证书路径
nginx -t && systemctl enable --now nginx
```

**两个必须注意的点：**

1. **`proxy_set_header X-Forwarded-Proto $scheme;` 不能删。** nginx 终结 TLS 后到达平台的是明文 HTTP，
   平台靠这个头判定实际是 HTTPS。缺了它，浏览器发来的 `Origin: https://…` 会和平台算出的 `http://…`
   对不上，表现为"HTTPS 配好了反而登录不上（403）"。平台只采信来自回环/内网对端的转发头，公网伪造无效。
2. **HTTPS 通了以后要关掉试用开关。** 平台会话 Cookie 用 `__Host-` 安全前缀，浏览器要求 HTTPS。
   试用阶段用 `APP_SESSION_ALLOW_INSECURE=1` 降级为普通 Cookie，正式启用 HTTPS 后**必须删掉这一行**：

   ```bash
   # 方式 A
   sed -i '/APP_SESSION_ALLOW_INSECURE/d' /etc/yonghong-platform.env && systemctl restart yonghong-platform
   # 方式 B
   sed -i '/APP_SESSION_ALLOW_INSECURE/d' .env && docker compose -f docker-compose.tencent.yml up -d
   ```

## 五、首次使用

1. 浏览器打开站点，用安装脚本打印的管理员账号密码登录（**系统强制修改初始密码**）；
2. 进「医院与权限」为科室同事分配医院、角色（角色权限就是左侧菜单勾选）与登录账号；
3. **数据准备中心入口**：左上角品牌区 4 秒内连击 **3 次** → 输入入口口令（默认 `yonghong`，
   在配置文件里改）→ 进入。平时页面上不显示任何入口；
4. 进去后两条路：
   - 想先看效果：「审核与发布」→ **一键载入示范数据并正式发布**（20 台设备的脱敏虚构数据，二次确认后执行）；
   - 上真实数据：「文件导入」→ 下载模板 → 填院内数据 → 导入 → 字段映射 → 质量门禁 → 业务复核 → 发布。
     **金额一律填万元**，模板下载区有明确标注。

> 示范数据是显式破例：由同一个管理员完成导入、复核、发布，绕过了"创建人不得复核自己批次"的职责分离门禁。
> 系统不会把它伪装成正常双人复核——复核事件记 `break_glass` 并写明理由，审计可按 `publish_break_glass` 检索。
> 正式院内数据仍须双人复核。

## 六、日常运维

| 操作 | 免 Docker | Docker |
|---|---|---|
| 查看日志 | `journalctl -u yonghong-platform -f` | `docker compose -f docker-compose.tencent.yml logs -f --tail=200` |
| 重启 | `systemctl restart yonghong-platform` | `docker compose -f docker-compose.tencent.yml restart` |
| 升级 | 上传新包 → `bash deploy/install-tencentos.sh`（配置与数据保留） | 上传新包 → `docker compose -f docker-compose.tencent.yml up -d --build` |
| 备份 | 停服拷 `/var/lib/yonghong-platform` 整目录 | `docker run --rm -v yonghong-data:/d -v $PWD:/b busybox tar -czf /b/backup-$(date +%F).tar.gz -C /d .` |
| 热备份（不停服） | 见下方脚本（用 Node 自带 SQLite，无需另装 sqlite3 命令） | `docker exec <容器名> node -e "…"` 同左 |

不停服热备份（服务器上已有 Node，不需要额外装 sqlite3）：

```bash
node -e '
const {DatabaseSync}=require("node:sqlite");
const stamp=new Date().toISOString().slice(0,10);
new DatabaseSync("/var/lib/yonghong-platform/platform.sqlite")
  .exec(`VACUUM INTO '/var/backups/yh-${stamp}.sqlite'`);
console.log("已备份到 /var/backups/yh-"+stamp+".sqlite");
'
cp -r /var/lib/yonghong-platform/r2 /var/backups/r2-$(date +%F)
```

建议：每天一次目录级备份 + 腾讯云快照，保留 30 天。数据资产只有这一个目录，没有别处状态。

## 七、配置项一览

| 变量 | 说明 |
|---|---|
| `BOOTSTRAP_ADMIN_EMAIL` / `USERNAME` / `PASSWORD` | 冷启动引导首个平台管理员（首登强制改密；账号建好后这三项就不再生效） |
| `DATA_WORKBENCH_ENTRY_PASSWORD` | 数据准备中心隐藏入口口令（默认 `yonghong`，**上线前务必改**） |
| `MFA_TOTP_ENCRYPTION_KEY` | 验证器密钥加密用，`openssl rand -hex 32`，**启用后不可更换**（换了已绑定的验证器会全部失效） |
| `APP_SESSION_ALLOW_INSECURE` | 仅内网 HTTP 试用置 `1`；HTTPS 后删除 |
| `TZ` | 东八区，默认 `Asia/Shanghai`。**不设会让"今天/本月/本年度"在 0—8 点整体错一天** |
| `PORT` / `HOST` / `DATA_DIR` | 端口 / 监听地址 / 数据目录 |

## 八、常见问题

| 现象 | 原因与处理 |
|---|---|
| 配好 HTTPS 后登录 403 | nginx 缺 `X-Forwarded-Proto $scheme`，补上并 `nginx -s reload` |
| 能打开页面但登不上，控制台报 Cookie | HTTPS 未生效却删了 `APP_SESSION_ALLOW_INSECURE`，二选一：把 HTTPS 配好，或先加回该行 |
| 上传 Excel 报 413 | nginx `client_max_body_size` 调大（示例配置给的 25m） |
| 报表日期差一天 | `TZ` 没设成 `Asia/Shanghai` |
| `npm ci` 卡住 / 超时 | `cp .npmrc.china.example .npmrc` 换国内源；或直接用包内 `dist/`，本就不需要 npm |
| Docker 拉基础镜像失败 | 配 `registry-mirrors`，或改用 `BASE_IMAGE=ccr.ccs.tencentyun.com/library/node:22-bookworm-slim` |
| 忘了管理员密码 | 停服务 → 删 `account_credentials` 里该用户名的行 → 恢复 `BOOTSTRAP_ADMIN_*` 三项 → 启动后用引导账号重新登录 |

## 九、后续演进（当前为单机试点形态）

- **SQLite → TencentDB MySQL**：需把 drizzle 迁移转 MySQL 方言并换驱动；单院试点用 SQLite（WAL）足够。
- **本地磁盘 → 腾讯云 COS**：`server-node/r2-disk.mjs` 是唯一对接点，接口只有 put/get/head/delete/list 五个方法。
- **横向扩容**：会话与数据都在单机，扩容前先完成上面两项。
- **等保合规**：口令强度、5 次失败锁定、操作审计、数据血缘均已内置；等保测评所需的日志留存周期与堡垒机接入按院内要求配置。
