# 勇虹医疗设备效益管理平台 · 本轮完善与重构说明

日期：2026-08-11
基线：腾讯云迁移包 v25（源码提交 `14902fe4`，99/99 测试通过）

## 一、本轮目标（对应业务诉求）

1. 后台自有账号体系：系统分配账号 → 归属某家医院 → 账号绑定角色 → 角色按左侧菜单勾选权限 → 账号密码登录。
2. 数据接入不依赖 HIS/PACS 在线对接：以数据准备中心的 Excel/CSV 上传、映射、清洗、复核、发布为唯一正式数据入口。
3. 隐藏入口调整：左上角品牌区 4 秒内连击 3 次 → 弹出口令框 → 输入口令（默认 `yonghong`）→ 进入数据准备中心；平时不显示任何入口。
4. 第一个专业分析模板「全面监测」：设备效益 / 设备效率 / 临床使用质量 / 患者体验 / 设备保障 五大类指标，全部由版本化指标目录驱动。
5. 指标计算口径可扩展：新增指标可携带加减乘除计算规则（安全公式引擎，不执行任意脚本），新增字段后指标仍可配置。
6. 驾驶舱布局灵活可配：选择模块/图表、拖动位置、调整大小，按医院保存布局。

## 二、账号与权限体系

### 2.1 模型（沿用既有 RBAC，新增凭据层）

```
hospitals ──< hospital_memberships >── accounts ──1 account_credentials（新增）
                     │                    │
                   roles ──< role_permissions >── permissions(17 项编码)
accounts ──< app_sessions（新增 auth_method: sso | password）
```

- 账号仍以邮箱为主键身份；`account_credentials` 为账号追加“登录账号（username）+ 密码哈希”。
- 密码使用 PBKDF2-SHA256（210,000 轮）加随机盐，仅存哈希；连续 5 次失败锁定 15 分钟；管理员分配的初始密码强制首次登录修改。
- 会话仍是既有 `app_sessions` 一套（HttpOnly Cookie、空闲 8h/绝对 24h、令牌只存哈希）；`auth_method=password` 的会话不再依赖统一身份网关请求头，锁定后需重新输入密码解锁。已启用 TOTP 验证器的账号，密码登录同样要求动态验证码。
- 统一身份网关入口保留，与密码体系共用账号、会话、权限模型，互不冲突。

### 2.2 系统分配账号（医院与权限 → 成员）

- 添加成员时选择医院与角色（原 invite_member 流程），随后可为成员“分配账号/重置密码”（新 `set_member_credential` 动作）。
- 越权防护：目标成员角色权限超出操作者权限时拒绝（重置他人密码等同接管账号）；全部写入审计日志。
- 冷启动：环境变量 `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` / `BOOTSTRAP_ADMIN_EMAIL` 首次密码登录自动创建平台管理员（强制改密），无需网关也能启动系统。

### 2.3 角色按左侧菜单勾选

- 新增菜单目录 `app/menu-catalog.ts`：每个左侧菜单声明其显示所需权限编码（与外壳 navItems 一致）。
- 角色编辑器新增「左侧菜单可见性」矩阵：勾选菜单即自动授予对应权限；取消勾选只回收不再被其他已勾菜单需要的权限；下方“功能权限”仍可逐项微调。
- 服务端继续只存权限编码（save_role 白名单校验），菜单勾选纯属配置体验层——不改变权限模型，后续新增菜单只需在目录中登记。

## 三、数据链路（无 HIS/PACS 对接）

保持迁移包已确立的四层数据区与治理链：

```
Excel/CSV 上传 → 原始批次(Raw) → 字段映射/清洗(Staging) → 复核对账(Curated) → 版本发布(Published)
                                                                       ↓
                                         驾驶舱 / 分析 / 报告 / 改进中心（只读已发布数据）
```

- 前台展示只消费已发布版本（published/demo/unavailable 三态），缺数据明确显示“暂无已发布数据”，绝不用演示值冒充。
- 隐藏入口：品牌区 3 连击 → 口令框 → `POST /api/workbench-entry` 服务端核验（默认 `yonghong`，`DATA_WORKBENCH_ENTRY_PASSWORD` 可覆盖）→ 进入数据准备中心。口令只是入口捷径；接口层仍逐一校验登录身份、医院成员关系与 `connector.manage`、`data.*` 权限。
- 原“驾驶舱空态直达数据准备中心”按钮同样只在解锁后出现，平时无任何入口暴露。

## 四、指标口径与「全面监测」模板

### 4.1 指标目录驱动

- 既有《医院指标基线》目录（17 项梳理 → 20 个可执行口径）保持不动，报告冻结与逐项审核激活机制不变。
- 新增「全面监测」目录 `app/comprehensive-monitoring-template.ts`（版本化，五大类 ≈29 项指标，编码前缀 `hospital.monitor.*`），与基线共用同一套“批量写入草稿 → 绑定来源 → 逐项审核激活”的治理流程。
- 模板注册表 `app/metric-template-registry.ts` 统一登记全部模板版本；数据准备中心可按模板选择批量导入，服务端校验版本与数量，冲突整批拒绝、幂等跳过。

### 4.2 计算规则（加减乘除）

- 新增安全公式引擎 `app/metric-formula.ts`：仅支持 `+ - * / ( )`、数字与指标/字段引用；递归下降解析，不使用 eval；除零 / 引用缺失 / 循环依赖一律显式“不可计算”，不产生伪造值。
- 指标定义新增可选 `formulaExpr`（如 设备利润 = 收入 − 成本、次均收入 = 收入 ÷ 检查人次），派生指标按依赖拓扑求值。
- 后续新增字段/指标：在数据准备中心定义字段 → 新建指标（可写公式）→ 审核激活 → 即可用于展示与模板，无需改代码。

## 五、驾驶舱布局配置

- 模块布局在原 12 列栅格上扩展：宽度四档（1/3、1/2、2/3、整行）+ 高度三档（紧凑/标准/加高）。
- 驾驶舱新增“编辑布局”模式：拖动模块调整顺序、调节宽高；“驾驶舱配置”页同步支持。
- 布局按医院保存在既有 `modules` 云资源（乐观锁、跨设备同步），旧数据无新字段时自动取默认值。

## 六、运营改进中心与报告导出（现状确认）

两个模块在迁移包中已成体系，本轮未重构、仅确认口径：

- 运营改进中心：预警 → 建议 → 负责人/期限 → 执行证据 → 复测记录 → 预期收益与已确认收益区分；新指标激活后即可作为改进任务的基线/目标值来源。
- 效益分析报告：模板库（按用途分类）→ 编制 → 复核 → 签发 → Word/CSV 导出 → 云端归档；保存时服务端重建质量结果并冻结指标模板版本与口径快照，历史报告不随模板升级漂移。

## 七、环境变量清单（新增部分）

| 变量 | 作用 | 默认 |
|---|---|---|
| `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` | 冷启动引导首个管理员密码凭据（配合 `BOOTSTRAP_ADMIN_EMAIL`） | 未设置则不启用 |

## 八、架构原则（为什么这样做）

1. **不写死**：菜单↔权限、模板↔指标、图表↔展示定义、布局↔云资源，全部目录/注册表驱动；新增项走配置与数据，不走代码分支。
2. **治理优先**：任何“正式”数值必须经过 导入→映射→清洗→复核→发布 链路；口径版本化、报告冻结快照、全链路血缘审计不动摇。
3. **安全边界在服务端**：连击与口令只是入口体验；所有接口继续做身份、成员关系、角色权限、医院范围四重校验。
4. **诚实数据**：published/demo/unavailable 三态贯穿始终；公式引擎对缺失、除零、循环显式失败。
5. **兼容渐进**：统一身份入口、既有指标基线、旧布局数据全部向后兼容；迁移仅前向追加（0011）。
