## 二、医院关注指标

已把医院提供的《医院设备管理指标计算口径与理论依据分析.xlsx》梳理为 20 项可配置指标，覆盖原文 17 个关注事项，并把不可混用的口径拆分为独立指标。每项指标保存定义、公式、分子、分母、单位、维度、粒度、责任部门、依据成熟度、数据准备度和版本。

关键边界包括：

- 检查人次按 `COUNT(DISTINCT examId)`，多部位检查仍计一次。
- 收入和成本只在检查级记录一次；部位分析按冻结的等分、权重或主部位规则分摊，金额守恒。
- 分子、分母或期间事实缺失时显示“数据缺失/待发布”，不按 0 参与结论。
- 自定义指标不支持的公式关闭失败，不静默退化为求和。

## 三、数据与安全边界

- 所有正式写入都校验应用会话、同源请求、医院租户、角色权限和数据范围。
- 原始文件、Raw/Staging/Curated/Published 快照均不可变，并校验 SHA-256 与行数。
- 直接患者身份字段在导入边界阻断；设备名称、文件名等非患者字段不会被误杀。
- 科室视图按归属投影并默认拒绝未知归属，防止跨科泄露。
- 发布、更正、回滚、隔离修复和 break-glass 均写审核与 lineage；发布人不能自审。
- 正式模式不回退到 MRI 等演示设备事实，也不能把演示改进任务写入医院云端。

## 五、腾讯云迁移边界

当前 Sites 版本使用 Cloudflare Worker、D1/SQLite 与 R2。源码、前端、迁移 0000—0010 和腾讯云迁移说明均已保留，但不能把现有 Worker 包直接当作腾讯云 Node/MySQL/COS 服务启动。迁移仍需完成：

1. Worker 入口改为标准 Node.js 服务或容器入口；
2. D1/SQLite schema 与 SQL 转换为 TencentDB MySQL；
3. R2 对象适配为私有 COS；
4. Sites 身份入口替换为医院认可的 OIDC/统一身份；
5. 完成脱敏迁移演练、权限回归、备份恢复和安全验收。

在线 HIS/PACS 接入不在当前范围；正式数据入口为受控 Excel、CSV、JSON 文件。
