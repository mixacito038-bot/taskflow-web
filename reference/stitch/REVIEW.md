# Stitch 原型审核：衡效智舱医疗设备分析平台

## 审核范围与结论

- 项目：`4871037464888449592`，共取得 6 个真实 screen 的 2560×2048 截图与 HTML；用户列出的 “Design System” 实际是 Stitch 的 `assets/...` 设计系统资源，不是 screen，因此没有截图或 HTML hosted URL，已归档完整 `DESIGN.md`、tokens 与 MCP 响应。
- 总体判断：视觉方向成熟，已形成“总览—台账—月报填报—单机详情—数据源—看板设计”的核心骨架；但目前更接近高保真静态概念稿，不宜直接按现状进入生产开发。
- 进入开发前必须补齐：统一数据口径与血缘、五维效益指标、页面中文化与导航一致性、移动/小屏策略、可执行交互与权限审批、图表单位和可追溯明细。

## 做得好的部分

1. 信息层级清楚：侧边导航、筛选区、KPI、趋势、结构分析、明细表的顺序符合管理驾驶舱阅读路径。
2. 经济效益主链路已成型：收入、全成本、净收益、ROI、回本/累计现金流、成本结构、同类设备组合分析均有入口。
3. 已考虑数据治理场景：数据源连接状态、字段映射、异常队列、数据质量分数与 `DEMO DATA` 标识都很实用。
4. 单机详情的“指标—趋势—健康摘要—告警—明细”结构适合设备科和管理层共同使用。
5. 设计系统强调高密度表格、tabular numbers、固定栅格、状态色和中英文搭配，方向符合医院后台系统。

## P0：上线前必须修改

### 1. 五维效益分析不完整

12 张业务材料要求同时回答经济效益、使用效率、临床质量、患者体验和设备保障。目前 6 个 screen 主要覆盖经济效益、部分使用效率、少量维护告警；以下内容缺失或只有导航/标签，没有实际页面：

- 临床质量：阳性率、增强率、检查部位/项目结构、高级功能使用、报告质量、质控完成率、技师/医生维度。
- 患者体验：预约等待、检查等待、报告时长、总诊疗时长、异常等待清单、患者流失/满意度关联。
- 设备保障：故障率、停机时长、MTBF、MTTR、PM 通过率/逾期率、保修状态、维保费用与工单闭环。
- 人员绩效：技师和诊断医生工作量、增强检查、特殊项目、班次分布、报告时长、阳性率、质控完成率。
- 全品类经营：品类收入、品类成本、品类收益、低效/紧缺/过配/可共享分类及资源配置建议。

建议新增 4 个一级分析域：“临床质量”“患者体验”“设备保障”“人员绩效”；总览只展示每域 1–2 个核心指标和告警，点击后进入专题页。

### 2. 数据口径和来源没有落到界面

高风险财务指标旁必须可查看：公式、统计周期、是否含税、权责/收付口径、归集时间、数据源、责任部门、更新时间、口径版本、审核状态。当前页面只有数值和同比/目标，没有这些审计信息。

最低口径建议：

| 指标 | 建议公式 | 主数据源 | 责任部门 |
|---|---|---|---|
| 设备收入 | 按检查/治疗完成时间归集的有效收费－退费 | HIS/收费系统、RIS/PACS | 财务处、信息科 |
| 全成本 | 折旧＋维修＋维保＋耗材＋人工＋能耗＋水费＋空间占用＋管理分摊 | 财务 ERP、资产、后勤、HR、耗材/工单系统 | 财务处牵头，资产/设备/后勤/人事协同 |
| 净收益 | 设备收入－全成本 | 指标中台计算 | 财务处 |
| 收益率/ROI | 净收益÷设备原值或购置投入；必须标注年度/累计口径 | 资产系统＋指标中台 | 财务处、资产管理部门 |
| 投资回收期 | 首次累计净现金流 ≥ 0 的期间；无回本则显示“未回本” | 收入、现金成本、购置投入 | 财务处 |
| 使用率 | 有效工作时长÷可用工作时长，或完成工作量÷标准工作量；两种口径不得混用 | RIS/PACS、IoT、排班 | 信息科、设备科、使用科室 |
| 故障率 | 故障次数÷开机时长或工作量；界面需写明分母 | CMMS/维修工单、IoT | 设备科 |

### 3. 示例数据存在跨页矛盾

- 总览筛选周期为 2026 年上半年，单机详情月表却是 2023 年；除总览外没有统一的“演示数据”提示。
- 单机详情显示“ROI 14.2% / On track (36 mo)”，累计现金流图的回本点却约在 Q3（约 18 个月），右侧又写“提前 3 个月”，三者不能同时成立。
- 总览：收入 ¥45.2M－成本 ¥18.7M＝净收益 ¥26.5M，算术成立；但相对 ¥850.4M 投入的当期收益率约为 3.12%，必须说明 ROI 是当期、年化还是累计。
- 单机 YTD 净利润 ¥1.24M 与 14.2% ROI 的投资基数未显示；累计现金流初始投入图示约 ¥1.1M，也不符合常见 3.0T MRI 资产量级，建议使用一致且可解释的演示数据。
- 成本结构 42%＋28%＋18%＋12%=100%，但仅包含折旧、维保、人工、耗材，遗漏维修、能耗、水费、空间和管理分摊，与业务材料的“全成本”口径不一致。

应建立一份平台级假数据集，由同一个计算层生成总览、台账和单机页面，不要在每页独立手填数字。

### 4. HTML 是静态稿，不是可运行原型

6 个 HTML 均没有表单提交、点击/变更处理器或业务脚本；筛选、保存、提交审核、发布、拖拽、同步、异常处理、导出等按钮目前只有视觉表现。开发验收需补齐：

- 加载/空数据/错误/无权限/部分成功/重复提交状态；
- 填报自动保存、字段校验、异常原因、退回修改、财务/设备/科室三级审核和月度关账；
- 看板设计器的拖拽、尺寸调整、撤销/重做、预览、版本历史、角色可见性和发布回滚；
- 数据源的连接测试、凭证轮换、同步日志、重跑幂等、异常负责人和 SLA；
- 图表点击下钻至设备/月份/原始凭证，并保留筛选上下文。

## P1：重要优化

### 信息架构与一致性

- 品牌在“衡效智舱 / Hengxiao Zhicang / Medical Analysis Platform”之间切换，logo 也不一致；应统一中文主品牌并将英文作为辅助。
- 导航顺序和命名跨页不一致，例如 `Machine Details`、`Equipment Benefit`、`Labor` 使用英文，而标题和业务用户主要是中文。建议全中文，并采用稳定一级菜单：总览、经济效益、使用效率、临床质量、患者体验、设备保障、人员绩效、设备台账、数据治理、报表与配置。
- `Equipment Ledger` 截图默认打开编辑抽屉，遮挡大部分列表；应分别提供“列表默认态”和“编辑态”，便于验收筛选、排序、分页和批量操作。
- Layout Designer 属于管理员配置，应从业务分析导航中分组到“系统配置”，并控制为管理员/数据管理员可见。

### 指标和字段完整性

设备台账至少应覆盖：设备编码、名称、型号、品牌、序列号、院区、使用科室、启用日期、购置日期、单价/原值、数量、资金来源、折旧年限/方法、残值率、原计划回本年限、责任人、状态、维保合同、保修到期、数据责任人、成本中心、收费项目映射、标准工作量、目标利用率。

月度填报除人工和耗材外，还需显示或自动带入：折旧、维修、维保、能耗、电费、水费、房屋/空间占用、管理分摊、停机损失；并标明“系统自动取数 / 部门填报 / 公式计算”和数据责任人。

### 图表可读性

- 总览趋势图需在标题/坐标轴明确“万元/百万元、月、财务收入/归因收入”，并支持显示精确值、同比和目标线。
- 成本结构使用条形图是正确的，但应增加金额与占比、去年同期、预算差异，成本项需扩充到全成本。
- 设备组合散点图应明确 X=使用率、Y=ROI、气泡=收入，并提供象限阈值依据、图例、标签避让和表格替代视图。
- 单机累计现金流应显示实际/预测两条线、投入点、回本日期、预测区间和数据截止日，避免只画一条粗线。
- Layout Designer 示例柱状图没有轴名、单位、图例；发布前必须通过图表完整性校验。
- 红绿状态不能只靠颜色表达，需同时使用图标、文字和可读状态标签。

### 响应式与无障碍

- 总览、台账、填报、数据源和单机页有部分 `md/lg` 断点，表格也有横向滚动，方向正确。
- Dashboard Layout Designer 没有响应式断点，左右固定面板加固定画布在窄屏必然溢出；建议明确“仅桌面编辑，平板/手机只预览”，或把左右面板改为可折叠抽屉。
- 业务图表需要键盘可达的工具提示、可下载数据和无障碍表格；图标按钮需要中文 `aria-label`；焦点、错误提示不能只依赖颜色。

## 与 12 张材料的匹配矩阵

| 材料主题 | 当前覆盖 | 缺口 |
|---|---|---|
| 总体五维框架 | 部分 | 患者体验、临床质量、设备保障专题缺失 |
| 经济效益与全成本 | 较好 | 水电/空间/管理/维修口径、公式血缘和审核缺失 |
| 使用效率 | 部分 | 有利用率，但缺开机/负荷/闲置、有效时长、峰值、标准工作量 |

| 患者体验 | 缺失 | 等待、报告时长、总诊疗时长、异常等待缺失 |
| 人员绩效 | 很弱 | 只有成本填报，缺技师/医生工作量与质量联动 |
| 单机分析 | 较好 | 缺同类横比、同比环比、故障/停机/维保成本完整视图 |

| 角色驾驶舱 | 部分 | 只有角色可见性设置，缺设备科/临床科室/管理层独立看板 |

## 推荐落地顺序

1. 先冻结指标字典、公式、来源、责任部门、审核和关账流程。
2. 用一套一致的假数据打通“台账—月度成本—总览—单机详情—数据源血缘”。
3. 补齐临床质量、患者体验、设备保障、人员绩效四个专题页。
4. 统一中文导航、品牌和状态体系，再实现交互与权限。
5. 最后完善响应式、无障碍、导出报告和看板设计器。
