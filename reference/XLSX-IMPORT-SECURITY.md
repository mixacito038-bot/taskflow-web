# XLSX 服务端导入安全依据

## 依赖选择

- OOXML 压缩包读取使用 `@excel.js/jszip` 0.1.0，并锁定精确版本；工作表 XML 使用 `saxes` 5.0.1 严格流式解析。二者均为直接依赖，便于锁文件和安全审计追踪。
- 解析器只读取共享字符串与工作表值节点，不加载宏、外链、连接、OLE、绘图或其他活动内容。
- OOXML 中公式节点 `<f>` 与缓存值节点 `<v>` 分离；本项目遇到 `<f>` 后固定返回 `[公式未采信]`，不会读取相邻缓存结果，也不包含任何公式求值器。

## 本项目强制边界

- XLSX 解析路径只接受 `.xlsx`；`.xls`、`.xlsm` 和扩展名伪装文件均拒绝。CSV、JSON 由同一受控导入 API 的独立解析器处理，不进入 OOXML 解析器。
- 文件默认最大 25MB；同时限制 ZIP 条目数、声明的解压体积、工作表数、每表行列、总单元格数和单元格字符数。
- OOXML 包含 `vbaProject.bin`、externalLinks、connections、OLE/embedding 或 customUI 时拒绝。
- 公式不执行，缓存值不采信；预览以 `[公式未采信]` 替代并返回告警。
- 超链接只保留显示文本，不返回链接目标。
- 合并表头会产生显式告警，字段映射前必须由用户确认。
- API 要求应用会话、同源请求、有效医院成员关系、platform/hospital 全院数据范围和 `data.ingest` 权限。
- `inspectOnly=true` 只返回文件元数据、SHA-256、表头、画像和有限预览，不持久化；正式提交会在服务端重新解析，将原件和 Raw NDJSON 快照内容寻址写入 R2，并把行级记录、hash 与 lineage 写入 D1。两种模式都不返回公式、宏、链接目标或嵌入对象。
